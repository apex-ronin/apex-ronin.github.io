FILE 04 / STAGE FOUR / HORIZONPre-release · early access

QA that runs the boring checks, so people do the hard ones.

Two Stage Four systems. Fleet Collision Lab turns repeatable validation into evidence packets; Seat Sniper watches inspection and scheduling windows for high-value openings.

Stage Four is not in general release. The previews below show designed behaviour, not shipped production integrations.

Preview 04.A

Fleet Collision Lab

Simulated preview

A validation run is a sequence of deterministic assertions against a build or record set. Failures capture the exact artifact that broke.

AssertionFixed, versioned, re-runnable
EvidenceArtifact retained per failure
JudgementHuman review, not auto-close
Target value$1,800/month contract
Preview 04.B

Seat Sniper

Design preview

Inspection slots appear and vanish in minutes. Seat Sniper polls availability across the windows you care about and notifies your coordinator when a slot fits.

Availability polling frequency is a design parameter, not a claim of real-time coverage.

Underneath

The orchestration stack is the actual product.

Products are surfaces. What makes them cheap to add is a shared substrate: durable workflow execution, structured browser automation, and an append-only provenance ledger.

Hermes

Architectural direction for message routing, dispatch, and operator alert delivery across active workloads.

Stagehand

Architectural direction for resilient, schema-guided browser inspection when public sources lack clean APIs.

DBOS

Architectural direction for durable, checkpointed workflow execution so interrupted runs resume cleanly.

Provenance ledger

Every read hashed, timestamped, and separated from downstream model interpretation.

24-hour compute utilisation across concurrent workloads is the operating target for this layer.
